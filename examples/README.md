# Examples Directory

This directory contains code snippets for the Blinky Time firmware. They are reference material, not built or tested by CI, and some have fallen behind the firmware (noted below). Device configurations are not examples any more: they are JSON files in `devices/registry/`, uploaded at runtime.

## Available Examples

### Generator Examples
- `generator_examples.cpp` - Creating, initializing and switching generators
  - How to create and initialize generators
  - Parameter customization examples
  - Audio-reactive generator switching
  - **Stale:** it includes `generators/Lightning.h` and a `Lightning` class. That generator is now `PlasmaGlobe` (`generators/PlasmaGlobe.h`). In the firmware, `RenderPipeline` owns the generators; see `render/RenderPipeline.cpp`.

### Effect Testing Examples
- `effect_testing_examples.cpp` - Universal effect testing framework (`effects/tests/GeneralEffectTests.h`)
  - General tests that apply to all effects
  - NoOp effect usage (pass-through for direct generator output)
  - Performance testing and validation

### Version Demo
- `version_demo.ino` - **Stale:** it uses `core/Version.h` and semver macros that no longer exist. The firmware version is now `FIRMWARE_VERSION` (`bN-<sha>`) in `types/Version.h`, generated by `scripts/build.sh`.

### Recovery Sketch
- `recovery-sketch/recovery-sketch.ino` - Minimal sketch that only blinks the built-in LED, to check that a chip runs at all.
  - **Do not upload it with `arduino-cli upload` or the Arduino IDE Upload button**; that can brick the nRF52840. For a bricked chip, follow the recovery steps in [CLAUDE.md](../CLAUDE.md) (`make uf2-upload` for a bare chip, or SWD recovery) and [docs/SAFETY.md](../docs/SAFETY.md).

## Contributing Examples

To add a new example:
1. Make sure it compiles against the current firmware headers
2. Include all necessary configuration files
3. Add a short description here
4. Test on a test device (`devices/test_devices.json`), flashed with `tools/deploy_local.py`
5. Submit a pull request
