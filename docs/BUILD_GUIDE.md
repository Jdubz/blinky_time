# Blinky Things - Build Guide

## Supported Hardware

| Board | FQBN | Core | Status |
|-------|------|------|--------|
| XIAO nRF52840 Sense | `Seeeduino:nrf52:xiaonRF52840Sense` | Seeeduino nRF52 (non-mbed), pinned | The deployed fleet |
| XIAO ESP32-S3 Sense | `esp32:esp32:XIAO_ESP32S3` | arduino-esp32 (not pinned) | Next generation only, see [NEXTGEN_ESP32S3_PLAN.md](NEXTGEN_ESP32S3_PLAN.md) |

> ESP32-S3 support for the current fleet was cut in March 2026. All active development targets the nRF52840.

**CRITICAL**: Never use `arduino-cli upload` or `adafruit-nrfutil dfu serial` on the nRF52840. They can brick the device. How to put firmware on a device is in [Flashing](#flashing) below and in [SAFETY.md](SAFETY.md).

## Environment Setup

### Prerequisites
- **arduino-cli 1.3.1** exactly. The version is pinned in `tools/firmware_toolchain.json`; any other version is refused.
- Python 3 with `pyserial` (`pip3 install pyserial`).
- Git Bash on Windows (the scripts are bash).

### Install the pinned toolchain (once per machine)
```bash
bash scripts/setup_toolchain.sh     # or: make setup-toolchain
```

This installs everything into `<repo>/.arduino/` (gitignored):
- the core pinned in `tools/firmware_toolchain.json` (`Seeeduino:nrf52@1.1.10`);
- exactly the libraries pinned there (Adafruit NeoPixel, arduinoFFT, ArduinoJson), plus TFLite at the commit in `tools/setup_tflite_lib.sh`;
- the core patches from `scripts/apply_core_patches.sh` (TinyUSB CDC fix, `patches/`).

`build.sh` and the Makefile build **only** inside `.arduino/`. Libraries in your own Arduino folders are never read. `tools/check_build_libs.py` fails the build if a library resolves elsewhere or a version drifts. **Never fix a build by installing libraries yourself.** Fix the pin and re-run `setup_toolchain.sh`. Details: [RELEASE_PROCESS.md](RELEASE_PROCESS.md#the-pinned-toolchain-every-machine).

**Important**: The core is `Seeeduino:nrf52` (non-mbed). The mbed core (`Seeeduino:mbed`) has header conflicts with Adafruit NeoPixel.

## Firmware Versioning

- `blinky-things/BUILD_NUMBER`: plain text integer.
- `blinky-things/types/Version.h`: generated by `scripts/gen_version.sh` (build number + git SHA). Do not edit it.
- Reported by `json info` as `"version": "b<N>-<sha>"`. A `--dev` build reports `b<N>-dev-<sha>`.
- `SETTINGS_VERSION` (config format, in `ConfigStorage.h`) is separate from the build number. Changing it resets saved tuning on every device.

**Release build numbers are assigned by the release workflow, not locally.** Fleet and new devices only get stable GitHub releases. See [RELEASE_PROCESS.md](RELEASE_PROCESS.md).

**Always compile with `scripts/build.sh`.** It regenerates `Version.h`.

```bash
./scripts/build.sh                          # compile check (bumps BUILD_NUMBER)
./scripts/build.sh --no-bump                # recompile without incrementing
./scripts/build.sh --dev                    # dev build: no bump, version b<N>-dev-<sha>
./scripts/build.sh --dev --ota-bench-key    # dev build that trusts the bench OTA key
./scripts/build.sh --build N                # exact build number (release CI only)
```

`make compile` also builds inside the pinned toolchain, but skips the version bump.

## Flashing

| Situation | Tool |
|-----------|------|
| Fleet devices (through blinky-server) | `./scripts/deploy.sh --devices=<ids or all>` (stable releases only) |
| A device on this machine's USB | `python tools/deploy_local.py --port COMx --device-id <id>` (stable by default; `--dev` / candidates only on a test device in `devices/test_devices.json`) |
| A personal device, from a browser | `blinky-time.joshwentworth.com/#firmware`, see [WEB_FLASHER.md](WEB_FLASHER.md) |
| A bricked bare chip, not yet in the fleet | `make uf2-upload UPLOAD_PORT=/dev/ttyACM0` |
| Bootloader | `./scripts/deploy-bootloader.sh`, on a sacrificial device first (see [bootloader/README.md](../bootloader/README.md)) |

Use `deploy_local.py --dry-run` first. Do not use `build.sh --upload` or a manual UF2 drag-and-drop on a configured device: they skip the identity, version and stability checks.

### UF2 bootloader (background)

The nRF52840 uses a UF2 mass-storage bootloader. `tools/uf2_upload.py` (Linux) and `tools/uf2_upload_win.py` (Windows) do the low-level copy:

```
compile → .hex → uf2conv.py (family 0xADA52840) → .uf2 → copy to the XIAO-SENSE drive
```

| Board | Drive Label | Normal VID:PID | Bootloader VID:PID |
|-------|-------------|----------------|---------------------|
| nRF52840 | `XIAO-SENSE` | `2886:8045` | `2886:0045` |

Double-tapping Reset shows the drive. Only do that by hand on a bare bench chip.

## Device Configurations

Device configs are JSON, uploaded to the device at runtime with `device upload <json>`. They are not compile-time flags; every nRF52840 device runs the same binary.

- **Fleet devices:** the config goes through the deploy.sh-gated fleet API (`device upload` needs the `X-Deploy-Tool` header). Never by direct `curl`.
- **A bench device on your USB:** `device upload <json>` over its serial port is fine.
- After an upload, wait at least 75 s of uptime before any reset (the 60-second rule in CLAUDE.md).

Config files live in `devices/registry/`, one per device ID (`<deviceId>.json`). See [devices/registry/README.md](../devices/registry/README.md) and [HARDWARE.md](HARDWARE.md).

## Multi-Platform Architecture

Platform detection is compile-time, in `hal/PlatformDetect.h`:

```cpp
#if defined(ESP32)
  #define BLINKY_PLATFORM_ESP32S3 1
#elif defined(ARDUINO_ARCH_MBED) || defined(NRF52) || ...
  #define BLINKY_PLATFORM_NRF52840 1
#endif
```

Platform-specific code is isolated in HAL implementations (`blinky-things/hal/hardware/`):

| Interface | nRF52840 | ESP32-S3 (next gen) |
|-----------|----------|----------|
| PDM mic | `Nrf52PdmMic` (hardware PDM interrupt) | `Esp32PdmMic` (I2S) |
| Flash storage | `InternalFileSystem` | `Preferences` (NVS) |

`./scripts/build.sh --esp32` and the Makefile `esp32-*` targets still exist for next-gen work. They are not under the pinned toolchain yet.

See [DEVELOPMENT.md](DEVELOPMENT.md) for more.

## Build Output

A b215 release image is about 485 KB (`blinky-things-b215.bin`: 484,764 bytes). The application slot leaves room for the bootloader and settings; `arduino-cli` prints the exact use and limit at the end of every build.

## Troubleshooting

### "Header conflict / redefinition of struct _PinDescription"
You're using the mbed core. The pinned toolchain uses `Seeeduino:nrf52`; re-run `bash scripts/setup_toolchain.sh`.

### `check_build_libs.py` fails, or `BLINKY_TINYUSB_CDC_PATCHED` `#error`
A library resolved outside `.arduino/`, or the core is unpatched. Re-run `bash scripts/setup_toolchain.sh`. Don't install libraries by hand.

### arduino-cli version refused
Install the version pinned in `tools/firmware_toolchain.json` (`arduino_cli`).

### Port locked / device not found
blinky-server, the MCP server or blinky-console may have the port open. blinky-server owns all serial and BLE connections on blinkyhost; on a workstation, close other serial sessions first.
